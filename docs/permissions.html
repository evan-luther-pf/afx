afx > Permissions

Permissions

afx separates ordinary development work from actions that need review. Permission checks happen when a tool executes, using the exact resolved action.

Modes

auto
The default. Routine work proceeds. Unresolved sensitive actions receive one bounded automatic review.
ask
Sensitive actions pause for human approval in the interactive interface.
yolo
afx permission prompts are disabled. Use this only inside an environment you already trust.

Rules

Configured denies are checked before allows. Narrow rules can match exact commands, paths, or tool actions. An approval request shown by auto mode is bound to one action; ordinary conversation does not approve it.

User settings live in ~/.afx/settings.json. Safe project defaults can live in .afx.json. Private credentials and permission grants do not belong in project configuration.

Headless requests

afx ask remains noninteractive by default. Add --prompt-permissions only when standard input is a terminal and a human can answer. JSON output stays on standard output; approval text uses standard error.
